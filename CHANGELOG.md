# Changelog

All notable changes to Foundry are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/), and the project aims to follow semantic versioning once it reaches 1.0.

**How this file is kept.** Every change to the shipped suite (`skills/`, `schema/`, `reference/`) writes its own entry under `[Unreleased]` in the same pull request, saying what changed and why; CI fails a pull request that skips it. A release rolls `[Unreleased]` into a dated version heading that opens with a "why this release" paragraph, and the GitHub Release is published from that body. The notes get written while the context is warm, so a release is a roll-up rather than an archaeology dig.

## [Unreleased]

### Fixed

- Site: the Supabase keep-alive at `/api/health` was a silent no-op and the project it protects was paused anyway. It pinged Supabase with an anonymous `auth.getUser()` and read the resulting `AuthSessionMissingError` as proof of a round trip, but supabase-js resolves that case from local state and never opens a socket, so eight consecutive green pings generated zero Supabase traffic; a client pointed at a hostname that cannot resolve returned the same `200 {"ok":true}`. Supabase documents the criterion as user database activity, so the target moved to the database. The endpoint now calls a stored `public.ping()` through PostgREST and reports healthy only when Postgres returns a parseable timestamp, an outcome nothing but a real query produces. The adversarial review of that fix found an older defect beside it: the route built a cookie-reading client, so a forged expired-session cookie turned one unauthenticated request into a Supabase token refresh plus stack traces in the log. It now uses a session-free client with a bounded timeout, and an in-process throttle holds the public endpoint to one real database query per minute so it cannot be used as a load lever against a free-tier pool shared with live sign-ins. Requires the `ping()` function and its `anon` execute grant to exist in the project; the endpoint returns 503 until they do, by design.

### Added

- Repo: the release procedure is written down (CLAUDE.md) and the changelog convention above is enforced mechanically. `scripts/check-changelog.mjs` runs in CI on every pull request and fails one that changes `skills/`, `schema/`, or `reference/` without touching this file, because release notes reconstructed months later are a worse record than the ones written in the pull request that earned them. The escape hatch is deliberate and visible: a `changelog-exempt` label, or a `Changelog-exempt: <reason>` commit trailer.
- Site: `scripts/check-brand-assets.mjs` and `scripts/check-built-mark.mjs`, the two brand gates, wired into `make validate`; `reference/brand-kit.json`, the design-kit pin; `scripts/og/card.html` and `scripts/og/rendered.json`, the share card's recipe and the digests of its source and its render; the kit's foundry icon set, web manifest and Safari mask icon under `public/`; `make og-card` and `make check-kit`.

### Changed

- Site: the hero's ambient glow is gone, and designed motion replaces it. The amber radial (a 28px blur on a 7s breathe) and the bone spotlight (which transitioned a gradient position, repainting the whole hero every frame the cursor moved) were both glows, which DESIGN.md's anti-goals ban, and the amber one put hue on the brand layer where only an invocable command belongs. In their place the hero carries a measuring band directly above the terminal panel and exactly its width: a lattice whose columns divide that width evenly, reading the pointer as a coordinate snapped to the nearest graduation, with a registration mark at the crossing. It is monochrome, animates transform and opacity only, is absent under reduced motion and on coarse pointers, and reports nothing off the band. Three passes of a critic that saw only screenshots and the anti-goals drove its placement: the first two floated with edges that aligned with nothing and took readings below the row where the lattice was still drawn.
- Site: the hero kicker's contrast is fixed at the root rather than by recolouring type. It measured 2.94:1 against WCAG AA's 4.5:1 with the glow behind it; no hairline now passes behind the hero's copy at all, and the same per-glyph pixel measurement returns 5.48:1 with zero glyph pixels below 4.5 at 1024, 1280 and 1440, with and without reduced motion.
- Site: the sticky header drops its `backdrop-blur`. DESIGN.md's Elevation section asks for depth from tonal layering and hairlines rather than a blur, and the audit measured the filter forcing a GPU readback on every scroll frame over the nine scroll-animating sections that are its backdrop.
- Design record: DESIGN.md gains the Motion section the workspace design-system policy requires: named tokens tagged with what each duration is for (never a range), the asymmetry rule, the reduced-motion requirement, and motion anti-goals. `--ease-out-quint` moves out of a bare `:root`, where no utility could reach it, into `@theme` alongside the durations.
- Skills: `production-audit`'s testing-confidence dimension now treats an unreachable control as a finding in its own right. A threshold hardcoded in the module that enforces it, a client constructed at import with no seam to substitute, an allowlist frozen in a module-scope constant: the code may be correct today and no test can ever demonstrate it stays correct. The finding lands on the untestable construction, and its remedy is the seam rather than the test.
- Skills: `brand-voice` states where a glossary comes from. Its terms are the builder's observed vocabulary, recorded as heard with a pointer to where it was heard, and a term the skill supplied rather than observed is marked assumed like any other drafted entry. A vocabulary invented at branding time teaches the product a language nobody speaks, so the builder keeps using their own word and the glossary becomes the rule everyone overrules. The BRAND template's glossary column asks for the provenance; the boundary is unchanged, this is observation and never an interview.
- Skills: `frame` adds cross-entry coherence findings. Nine entries checked one at a time all pass while the page contradicts itself: a non-goal that excludes the named user, a success measure that cannot move even if the stated problem is solved, an alternative called adequate beside a problem that says people are stuck. The audit now makes one pass across entries and reports contradicting pairs, without picking a winner, because which entry is wrong is the builder's call.
- Skills: `phase-plan` and the plan template sharpen the handoff in three places. A phase that cannot start yet now says so in the index line itself (`gated: <what it waits on>`), because an unstarted phase and a blocked one looked identical to the reader the index exists for. The plan anatomy gains an owner-tagged `## Open questions` section, the unsettled half of Kickoff decisions, since a question nobody owes an answer to is how a plan stalls with nobody noticing. And a dependency may now be something that must be *proven*, a named hypothesis plus the proof that would clear it, which is the honest shape when the next unit rests on something still unverified.
- Brand: the mark is the Horizon Foundry design kit's 2026-09-19 revision, and the drawing before it is retired everywhere this site serves. The chrome lockup, the deck's title slide, the favicon set, the web manifest and the share card all move together; the kit ships two cuts of the mark chosen by rendered width (48px wide is the line), so every placement now states which cut it asks for, and each cut carries its own viewBox. The favicon set is the kit's foundry set, a bone mark on an ink tile, which is the inverse of the parent studio site's and is what keeps the two sites apart in a row of tabs. The share card had no recipe at all, which is why it still carried the retired mark and a pre-Archivo display face months after both were replaced; it is now generated from a committed `scripts/og/card.html` whose regeneration command lives in its header.
- Public surfaces: two gates hold the mark to the kit. `scripts/check-brand-assets.mjs` checks every copied file, both transcribed paths, the manifest's declared divergences, and the share card's source AND its render against `reference/brand-kit.json`; given `--kit <path>` (that is `make check-kit`) it also checks that pin against a real kit checkout, including the kit's whole `web/` tree as a set, so a kit revision that adds or renames an asset cannot pass. `scripts/check-built-mark.mjs` sweeps everything the build emits (the server chunks that render the on-demand routes included, and the standalone bundle the image actually runs) plus every source file, asserts that every placement on every prerendered page references a symbol defined on that page at the cut its size requires, and asserts the whole icon and manifest tag set. `make validate` therefore reads built output and requires `npm run build` first.
- Public surfaces: the first version of both gates was defeated five ways by an adversarial pass and rewritten, and two further passes over the fixes found nine more and then seven more, each round's most useful finding being one that round's own fix had introduced (a file whose name git quotes fell outside every sweep; then a derived allowlist that failed unsafely on a partial parse). Every hole from all three rounds was re-run against the current gates and now fails. What each was, and the through-line, is in NOTES (2026-09-22).

- Design record: this repo stops reading as the owner of the Horizon Foundry palette. DESIGN.md now states, per token, which four values are inherited from the parent brand (ink, bone, slate, amber) and which are this product's own extension for its own dark surface, and the two aliases name the parent values they alias: `command` is the brand amber, `brand-slate` is the brand slate. Neither is renamed, because renaming would churn every token reference for a naming preference. BRAND.md's opening no longer calls itself the identity source of truth, and `app/globals.css` stops describing the brand as "slate + white" (the parent's light value is bone, and has been since before the design kit existed). No colour value changes.
- Design record: DESIGN.md's anti-goal "no color that does not mean a severity or a verdict" now names the third case it always had in practice, an invocable command, which the Colors section has codified since 2026-07-13; and the design-system page's neutral ramp gains a `line-strong` hairline so its two darkest swatches read as chips rather than as empty outlines on a ground of their own value. Both were found by a critic that saw only the rendered page and the anti-goals.
- Skills: phase-plan's index entries carry the plan's written date and the Phase Plans list becomes chronological append-only, so the last line is the most recently written plan and a cold session can see the current frontier without opening files. The plan template gains a `Written: YYYY-MM-DD` line beside `Status:`, the checkbox now means closed for any reason (merged, superseded, abandoned) with an annotation naming why, and a status transition in the plan file must mirror to the index entry in the same action. Terminal entries (decision required, awaiting evidence, no next work selected) get a defined dated form and checkbox meaning, and a stated migration posture keeps the new rules from turning every pre-existing index into a mass reformat: apply them going forward, backfill only what evidence supports, and never reorder history. Motivated by a real index audit: thirteen entries, no dates, four merged phases still unchecked, six entries pointing at deleted plan files, and two active plans never indexed, leaving no way to tell recent from stale after a context clear.

## [0.2.0] - 2026-08-14

**Why this release:** v0.1.0 made the suite public; v0.2.0 makes it verifiable in execution and complete across the lifecycle. (A v0.1.1 was planned and never tagged; its content ships here.) A comparative audit against the strongest public practice of skill engineering surfaced one theme, the gap between a skill that reads well and a skill whose run can be checked from the outside, so every skill now anchors its opening gate to a numbered procedure, every step ends in a named check or artifact, degraded runs declare themselves, and the suite keeps exactly one inspector. Two skills joined: readout, the display side of measurement, and feature-design, the eleventh skill and the keeper of a sixth promise, auditing a declared design against the actual repository before any plan is written. The suite also learned to say what version it is and when it is behind: a repo-root VERSION stamped into every skill, a disclosed daily update check whose whole contract lives in the command that runs it, and public surfaces rewritten from comfortable absolutes to the precise claim. Both public audits were regenerated under the current method, with the one confirmed risk fixed in-branch before publication. The bar this release keeps: trust the transcript, not the prose.

- Skills: feature-design joins the suite, the eleventh skill and the keeper of a sixth promise (the design is checked against the code before it is built). The builder declares a feature in six entries; the skill audits the declaration against the actual repository and leaves a grounding table, because the answers a design interview asks for are not in anyone's head, they are in the code. Authoring-time design-vs-repo contradiction checking is the one mechanism a survey of the field found unserved: existing tools check after implementation and resolve disagreement by changing the code.
- Skills: feature-design hardened before its first release, by two reviews and one dogfood run. A hostile reader and a literal protocol execution against a real declared feature in another repo, confirmed by a follow-up verification agent, bounded the question channel (a labeled report section, never a conversation, and more questions than findings is a red flag), gated every handoff on the Confirmed stamp, made the reverse pass a mandatory table section even when empty, and added the declaration-tense gate, so a declaration describing already-implemented work flips to a divergence audit instead of a fiction. A fresh agent then ran the skill against a from-memory declaration; the run held (full grounding table, zero questions, no files written) and its reverse pass caught exactly the finding class the skill exists for, a declared symbol the consuming page never uses, which also taught the reverse pass to audit at the granularity the declaration itself chose.
- Reference: doc-set-spec declares where a confirmed feature-design declaration lands, because the dogfood run found the suite's own doc set never said. Absent a project-declared design-records location, the declaration folds into the next unit's plan via phase-plan and its decisions with their rejected alternatives land in NOTES.md; that fold-in is the declared home, so the skill's undeclared-home finding does not fire on a conforming doc set.
- Skills: added `readout`, the tenth skill and the display side of measurement. `instrumentation` makes numbers exist and ends when reliable events do; `readout` reviews the surface that shows them, where every number can be individually correct and the surface still misleads (a rate beside a count on a different window, a throttled source rendering as a zero, a period spanning the release that changed what it measures). It pitches each surface at a named reader and their decision, and ends in a rendered review by someone who did not build it. `instrumentation` now hands off to it in a numbered step rather than instructing a dashboard build, and `production-audit`'s operability and ui dimensions cite it for whether a surface can be read rather than whether it exists.
- Public surfaces: `make validate` now runs `scripts/check-skill-surfaces.mjs`, which fails the build when a skill is missing from `lib/skills.ts`, the README table, or PRODUCT.md's suite list, and when any present-tense "<n> skills" claim disagrees with the real directory count. It caught this release's own drift: adding the tenth skill left the README opening, the homepage hero, and both deck slides claiming nine.
- Site: the `/skills` "Your reports" tile now always renders. It was conditional on an odd user-invoked skill count to keep the grid square, so the tenth skill would have silently removed the only `/unlock` entry point outside the footer.
- Docs: reworded one NOTES.md decision entry and one skill-authoring phrase; added a house style rule to CLAUDE.md.
- Skills: an execution-quality pass over all nine skills. Every skill now carries a numbered procedure its opening gate points at, with each step ending in a named check or artifact, because an unanchored "todo per step" gate was ceremony in the four skills that had no steps. `foundry check` is rewritten as prepare's read-only preview: it cites existing records and reports staleness instead of re-inspecting what the audit inspects, and `prepare` gains an authority envelope. production-audit adds a risk/improvement decision table, a verbatim subagent brief, a quote-the-motivating-line rule, a verification floor (every risk is verified), and release-safety depth (artifact identity, post-deploy verification). mobile now leaves a filled verification matrix as its artifact; instrumentation's plan table carries the guardrail and owner; frame's confirmation is a dated stamp; brand-voice branches modes off the approval header and leaves a per-surface apply report; scaffold verifies its own placeholders before finishing; document gains per-mode procedures, a mechanical sanitization sweep, and a cold-start drill.
- Reference: skill-authoring adds anchored gates, evidence-per-step, declared degradation, retrieval honesty, and requalification; doc-set-spec adds the lesson-promotion ladder and defers plan-chain mechanics to phase-plan; new reference/templates/plan.md.
- Site: the brand mark replaced with its canonical clean vector (21 points, a few hundred bytes) in the favicon and the header symbol; the previous asset was a raster auto-trace (about 1,340 stair-step points, ~21 KB inlined per page). Silhouette verified unchanged by overlay; the mark's usage spec lives in the brand repo.
- Site and README: the value prop simplified to one definition sentence used verbatim on every surface, with the receipt beside it. The README leads with install above the pitch and one-line skill pitches; the homepage hero drops the stacked framings and the five promises move below the install block; the deck unpacks its suite slide into promise items and keeps two quotes instead of eight; check's copy reads as prepare's read-only preview everywhere; the audit's honest limit (not a penetration test) is stated on the run-it section and the README.
- Brand: adopted Big Shoulders as the display face, replacing Inter, matching the parent brand's decision (horizon-foundry/horizon-foundry) and the studio site's companion change. Display headings and the wordmark move from 600 to 700 weight. DESIGN.md and BRAND.md updated; the canonical site URL moves to `https://foundry.thehorizonfoundry.com`.
- Skills and repo: the suite now carries a version marker, because an installed skill had no way to say what it is. A repo-root `VERSION` file is the single source of truth; `make sync-version` stamps it into every SKILL.md frontmatter (`version:`) and the site's version constant, and `make validate` fails on drift, the same discipline as the bundled schema copy.
- Skills: every skill ends with a standard "Version check" section: a disclosed, rate-limited update check (at most one request a day per home directory, 10s timeout, silent on failure, never blocks a run), so an `npx skills` install, which is a one-time copy, learns when it is behind and tells you to re-run the install command. The whole contract, including the `FOUNDRY_NO_VERSION_CHECK` opt-out, is enforced in the command itself, not promised in prose, because a privacy control that exists only as prose is a hope. What is sent is the skill name and installed version, nothing else; the README's "Version check" section is the full disclosure.
- Skills: the instrumentation doctrine now states the narrow exception this check instantiates: a version check that serves the user, fully disclosed, opt-out enforced in the command, no identity attached, never blocking. Everything beyond that stays banned for tools running in someone else's environment. The homepage install block, SECURITY.md's scope, and the product frame's trust boundary were rewritten in the same change, from "sends nothing anywhere" to the precise claim, because the absolute was no longer true and an absolute that is almost true is worse than the truth.
- Site: new `/api/version` endpoint answering with the current released version (Cache-Control: no-store), and capturing the check as the `skill_version_check` event on a synthetic actor with person-profile processing off: check counts only, never uniques, no user, install, or IP identity, and only for the canonical skill names.
- Site: the one risk the 2026-08-14 self-audit confirmed is fixed. Next.js moves to 16.3.1, clearing an unauthenticated Server Actions CPU-exhaustion DoS (GHSA-m99w-x7hq-7vfj) along with the sharp, postcss, and server-function-disclosure advisories, and `poweredByHeader` is off. Two skeptic-verified truth defects fixed in the same wave: the homepage self-audit section now derives its verdict hue from the report's actual verdict through a full-literal class map instead of hand-rolling the risk color around a dynamic value, and the CI workflow's comment says a bad change is detected on main rather than claiming a merge gate no ruleset yet enforces, naming the tracked ruleset item.
- Reports: both public audits regenerated under the current method, because the published pair described a suite three changes old (readout, the version check, feature-design), and a self-audit describing a prior version of the suite is the same drift as stale marketing copy. The new self-audit (foundry-2026-08-14, ten dimensions, six adversarial skeptics) reads safe to ship within static scope with zero risks and 39 improvements; its one confirmed risk (the Next.js DoS above) was fixed in the same branch before publication, and five candidates were downgraded on the reachable-today rule with refutation notes recorded. The illustrative Perch example was re-authored to schema v4 and the current method (risk and improvement kinds, every risk verified, the quote-the-motivating-line rule, gate policy resolution stated), ending ready to ship, risks noted, with four verified risks. The 2026-07-16 and 2026-07-12 reports retire in the same change.

## [0.1.0] - 2026-07-17

Initial public release. The suite is nine Claude Code skills:

- **foundry**, a one-command pre-ship conductor that resolves the project's release policy, scores its gates (check) or closes them (prepare), and defers the authoritative verdict to one independent production-audit run.
- **production-audit** (flagship), a whole-application audit across six core dimensions plus the conditional dimensions the project's surface implies, ending in a scope-qualified ship or no-ship verdict, emitted as JSON against a versioned schema.
- **frame**, the one-page product frame (plus a four-line security frame) the builder declares and the skill audits before anything gets built.
- **scaffold**, **document**, **mobile**, and **instrumentation**, the user-invoked disciplines that get a product to production-ready.
- **phase-plan** and **brand-voice**, the model-invoked disciplines that keep the plan chain unbroken across sessions and one voice across every surface.

Ships with the marketing site, a Behind-the-Build hub, and a sign-in-gated reports section (Supabase magic link, per-owner visibility) that renders every published audit through one template.
